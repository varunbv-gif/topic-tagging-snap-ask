The same twenty conversations, tagged twice. Before: one model call per conversation against a shortlist, one tag out. After: the five-stage cascade — split the conversation into the questions the student actually asked, then tag each one. Every name checked against the tree before it is written.

The four findings worth acting on

How this run was produced

No API key was available in this environment, so stages 1–3 — the three model calls — were answered by a human following the prompts, and written into the run cache keyed by each prompt's hash. Stages 0 and 4, the payload assembly and the validator and aggregator that produced every number above, are the real code and ran untouched. These figures show what the method produces when followed carefully; they are not a measurement of what an unattended pipeline produces. Nor are they accuracy: no human-labelled reference set exists yet, so “tagged” means the tag landed on a real node, not that it landed on the right one.
