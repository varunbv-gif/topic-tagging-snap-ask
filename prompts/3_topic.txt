Same conversation, same summary. The chapters are settled. Now pick the exact topic
nodes inside them. This is the last step.

Rules
1. Return the node's ID, not only its name. Some chapters list the same name twice
   and a name alone cannot be resolved to one node.
2. Copy names EXACTLY as listed.
3. Return one node per distinct thing the summary says was covered, under the
   chapter it belongs to. A conversation that worked through five parts of one
   chapter gets five nodes. One that asked a single question gets one. Do not pad
   the list with nodes that merely belong to the same chapter.
4. Order the nodes within each chapter by how much of the conversation each
   accounted for, the largest first.
5. If a chapter is right but no node inside it fits what was covered, return
   "CHAPTER_ONLY" for that chapter with an empty topic_id. That is a real and useful
   answer. Forcing a node that does not fit is worse than admitting none does -
   "Miscellaneous examples" exists in several trees and is almost never the right
   answer.
6. Some nodes are far more specific than others in the same chapter. Prefer the most
   specific node the summary actually supports. Do not reach for a specific node on
   a detail the summary only hints at.
